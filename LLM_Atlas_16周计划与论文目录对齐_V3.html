05 · Feasible experiments

按你的算力规划，而不是按论文规模训练

以下显存范围是保守的实践预算，不是正式 Benchmark 或显存保证值；实际峰值会受模型精度、上下文长度、CUDA/PyTorch 版本与并发程序影响。

LEVEL 00 · BASELINE

CPU / 小模型

不占用服务器 GPU

优先验证研究想法、数据流程与评测逻辑；不是每项实验都必须上大模型。

  • 0.3M–5M 参数 MiniGPT
  • BM25、SQLite、FTS5、规则 Verifier
  • 轻量 Embedding 与离线对照实验
LEVEL 01 · DEFAULT

RTX 5060 · 本地主力

8GB 物理显存 · 建议留出余量

以 0.6B–1.7B Qwen3 系列为主；量化推理优先 4-bit，避免默认用 7B/8B 长上下文。

  • 0.6B 微调：短序列 LoRA，microbatch 1
  • 1.7B Q4：RAG、Agent、Memory、Self-Refine
  • 上下文先用 1K–4K Token，小批量跑评测
LEVEL 02 · STRICTLY OPTIONAL

共享服务器 · 单张 A40

单卡 48GB · 非独占资源

不把 5 张卡当作你的可用配额；仅在与同事协调并确认空闲后，选择 1 张卡短时实验。

  • 选做 1.7B–3B QLoRA 或 0.6B 教学式 RL
  • 尽量把自己程序的目标显存预算控制在约 16GB 以内
  • 可中断、能恢复、设置运行时限
⚑
共享资源保护原则：每次先查看 nvidia-smi、确认 GPU 使用许可和空闲显存；不抢占具身实验、不开多卡训练、不默认占满单卡 48GB。配置内存目标不等于硬性显存隔离，不能只依赖环境变量或 PyTorch 分配器保证不干扰别人。

每周读论文的四个问题

即使只花 30–60 分钟泛读一篇，也尽量写下下面四项：

  1. 它解决的核心问题是什么？
  2. 它改进的是模型参数、Prompt、工具还是系统？
  3. 实验是否真的支持作者的结论？
  4. 如果缩小到 0.6B–1.7B，我能复现哪一个机制？
